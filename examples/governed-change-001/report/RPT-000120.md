## Owner-defined defect and why a wider allowlist was refused

`DEFECT_ID = F4_ORDINARY_SERVER_RESPONSE_CLASSIFICATION_INCOMPLETE`

The predecessor recognised an affirmative server response by SQLSTATE family
alone, and only families `42` and `23`. Every other ordinary server failure fell
into the tier-3 message heuristic, so transport-looking text turned it into
`CONNECTION_LOSS` -> `DIRTY_PARTIAL_STATE` -> exit 6.

Adding `40001`, `HY000`, `1213`, `1205` and `3024` to a list would not have
established that the resulting precedence was correct. The model was
reconstructed from what each field of a PDO MySQL error attests.
`PDOException::errorInfo` is `[SQLSTATE, driver error number, driver message]`,
and MySQL partitions the **error-number** space by **origin**: 2000-2999 are
client `CR_*` errors describing the client's own socket, while 1000-1999 and
3000-5999 are server `ER_*` allocations. A server error number can only reach
the client inside a server `ERR` packet, so its presence **proves** the round
trip completed. SQLSTATE cannot carry that proof, because MySQL maps large parts
of both spaces onto the catch-all class `HY000` — `HY000`/`1205` (ordinary) and
`HY000`/`2006` (loss) share a SQLSTATE and are opposite verdicts. That is the
architectural reason the family list could not be completed by widening it, and
why the defect recurred.

## Correction

One production file changed:
`src/Xotlist/Infrastructure/Persistence/Mysql/Migration/PdoConnectionLoss.php`

* **Tier 1 — authoritative transport evidence -> loss.** SQLSTATE class `08` or
  a recognised client connection error number (2002, 2003, 2006, 2013, 2055).
  Produced by the client about its own transport and unmanufacturable by a
  server reply. Where it contradicts tier 2 the combination is not producible by
  PDO MySQL; loss is the fail-safe reading.
* **Tier 2 — authoritative server-response evidence -> ordinary.** A
  server-allocated error number, or — only when no error number exists — a
  SQLSTATE class no client raises (`0A`, `21`, `22`, `23`, `40`, `42`, `44`).
  Class `08` excluded as transport evidence; class `HY` excluded as
  origin-ambiguous. Message text is not consulted. **This is the corrected
  defect.**
* **Tier 3 — probe-free transport hint.** Reached only by exceptions carrying no
  server error number and no server-only SQLSTATE, i.e. client-raised ones, so
  the message is the client's own account of a client-side failure rather than
  server-chosen text. Terminal tier for `indicated()`.
* **Tier 4 — `classify()` only.** One read-only same-session `SELECT 1` on the
  owning PDO. Alive is ordinary; a false statement, missing row, empty row,
  `PDOException` or any other `Throwable` is loss.

`serverErrorNumber()` reads only `errorInfo[1]`, never
`PDOException::getCode()`, which carries the SQLSTATE rather than the MySQL
error number.

### Ambiguous-failure adjudication (task section 6)

Completing tier 2 by origin removes every server-originated error from tier 3.
That **reverses** `REV-000114` CONTROL 17 (`HY000`/`1000` + transport text +
alive session) from `CONNECTION_LOSS` to `ORDINARY`, because `1000` is a
server-allocated error number and the server therefore demonstrably answered.
The reversal is asserted explicitly as control `B3` and is a consequence of the
same fix the owner ordered for CONTROL 18.

The tier-3 hint was **retained ahead of the probe in `classify()`, but not
blindly**. After tier 2 is complete by origin, tier 3 can only be reached by an
exception the client raised with no server error number, where the message is
genuine client evidence rather than server text — a different justification from
the failed structure. Demoting it below the probe would change the verdict only
on a combination PDO MySQL cannot produce: the accepted persistence-v4 profile
pins `PDO::ATTR_PERSISTENT => false` and forbids reconnect-and-resume, and PDO
performs no auto-reconnect, so a session that genuinely lost transport cannot
answer a later `SELECT 1`. Task section 16 forbids treating a physically
impossible combination as decisive proof, so the ordering is recorded as a proof
limitation rather than claimed as proven, and both verdict classes it could
affect are independently anchored by producible controls.
